# Консольний застосунок для обробки товарів

## Призначення

Проєкт реалізує лабораторну роботу № 3: читає товари з CSV-файлу, перевіряє записи, обчислює підсумкові показники та виводить звіт у консоль і файл.

## Модель даних

`BakeryItem` — абстрактний sealed-базовий клас зі спільними властивостями. Об'єкти створюються фабриками `Bread.create(...)`, `Pastry.create(...)` або `BakeryItem.fromCsv(...)`, які перевіряють інваріанти до виклику конструкторів. Підтипи — `Bread` і `Pastry`; кожен реалізує власний розрахунок маржі. Контролер викликає `calculateMargin()` через спільний тип, без перевірок підтипу.

Категорії визначені enum `BakeryKind`: `BREAD` (`хлiб`), `PIE` (`пирiг`), `CONFECTIONERY` (`кондитерський`), `COOKIE` (`печиво`) і `BAKED_GOOD` (`випiчка`). Хлібна маржа враховує 5% виробничих витрат від собівартості; маржа інших виробів — 10% витрат на пакування.

`equals()` і `hashCode()` порівнюють вироби за назвою, категорією, вагою, собівартістю та ціною.

У варіанті 25 до даних виробу також належить час випікання. Поточна модель `BakeryItem` цього поля не має, і поточний CSV його не зчитує; наведені нижче контракти описують наявну модель і не трактують час випікання як реалізовану властивість.

## Порівняння з лабораторною роботою № 2

Збережено формат CSV, валідацію рядків, загальну вагу, пошук найдорожчого товару та структуру звіту. У ЛР3 формулу маржі винесено в підтипи: для однакових прикладових даних середнє значення змінилося з `22.00 грн` на `19.95 грн` через додаткові витрати.

## Формат вхідного файлу

Кожен рядок містить п'ять полів, розділених крапкою з комою:

```text
Назва;Тип;Вага;Собівартість;Ціна
Хліб пшеничний;хлiб;500;22.00;38.00
Печиво;печиво;200;30.00;58.00
```

Файл має бути в UTF-8. Десятковим роздільником може бути крапка або кома.

## Перевірка даних

- Має бути рівно п'ять полів; назва й тип не можуть бути порожніми.
- Тип має відповідати одному зі значень `BakeryKind`.
- Вага має бути цілим невід'ємним числом.
- Собівартість і ціна мають бути скінченними невід'ємними числами.
- Некоректний рядок потрапляє до звіту з номером і причиною помилки; інші рядки обробляються далі.

## Контракти запитів до даних

Усі запити працюють із результатом послідовного читання CSV. Коректні записи створюють `BakeryItem` (`Bread` для `BREAD`, інакше `Pastry`) і додаються до `List<BakeryItem>` у порядку файлу. Некоректні рядки не потрапляють до цієї колекції; причини зберігаються у `List<String>` у порядку рядків CSV.

| Запит | Тип елемента | Джерело | Тип результату та очікуваний результат |
|---|---|---|---|
| Список коректних товарів | `BakeryItem` (`Bread` або `Pastry`) | Вхідний CSV після перевірки кожного рядка | `List<BakeryItem>` у початковому порядку; містить лише прийняті записи. |
| Список помилок | `String` | Вхідний CSV під час перевірки рядків | `List<String>` у порядку появи; повідомлення містять номер рядка й причину відхилення. |
| Загальна вага та середня маржа | `BakeryItem` | Список коректних товарів | `MainController.WeightMargin(double totalWeight, double averageMargin)`. Вага — сума `weightG`; середня маржа — сума `calculateMargin()` / кількість товарів. Для порожнього списку обидва значення дорівнюють нулю. |
| Найдорожчий товар | `BakeryItem` | Список коректних товарів | `BakeryItem` з найбільшою ціною або `null`, якщо список порожній. Якщо ціни однакові, результатом є перший товар у файлі. |

### Контракти запитів із варіанта, які ще не реалізовані

За варіантом 25 виріб має містити назву, вид (`BakeryKind`), вагу, собівартість, ціну та час випікання. У поточній реалізації час випікання відсутній. Джерело для кожного запиту нижче — лише список коректних `BakeryItem`; помилкові CSV-рядки до запитів не входять. Ці контракти описують очікувані типи й поведінку, а не наявну функціональність.

| Запит | Тип елемента | Джерело | Тип результату й контракт |
|---|---|---|---|
| Фільтр за маржею понад поріг | `BakeryItem` | `List<BakeryItem>` коректних товарів і заданий поріг | `List<BakeryItem>` з товарами, для яких `calculateMargin() > threshold`; рівність порогу не проходить. Початковий порядок зберігається. |
| Перетворення товарів на список назв | `BakeryItem` | `List<BakeryItem>` коректних товарів | `List<String>` з `getName()` у початковому порядку; повторювані назви не вилучаються. |
| Групування за видом із середньою маржею | `BakeryItem` | `List<BakeryItem>` коректних товарів | `Map<BakeryKind, Double>`: для кожного наявного виду — середнє `calculateMargin()` його товарів. Види без товарів у мапу не додаються. |
| Статистика ваги | `BakeryItem` | `List<BakeryItem>` коректних товарів | `IntSummaryStatistics` за `getWeightG()`: кількість, сума, мінімум, максимум і середнє. Для порожнього списку стандартний результат Java: count і sum — `0`, average — `0.0`, min — `Integer.MAX_VALUE`, max — `Integer.MIN_VALUE`. |
| Пошук за назвою | `BakeryItem` | `List<BakeryItem>` коректних товарів і задана назва | `Optional<BakeryItem>`: перший точний збіг назви в порядку CSV або `Optional.empty()`, якщо збігу немає. |
| Топ-5 за маржею | `BakeryItem` | `List<BakeryItem>` після відхилення некоректних CSV-рядків | `List<BakeryItem>`: спочатку відфільтрувати коректні записи під час читання → відсортувати за маржею за спаданням → за однакової маржі за назвою за зростанням → взяти не більше п'яти. Якщо маржа й назва однакові, зберігається початковий порядок. |

Для `data/input.csv` поточні запити повертають 2 коректні товари та 4 помилки. Реалізовані агрегати: `WeightMargin(700, 19.95)`, найдорожчий товар — `Печиво (58.00 грн)`. За контрактами запитів із варіанта статистика ваги мала б count `2`, sum `700`, min `200`, max `500`, average `350.0`; середня маржа за видами — `BREAD: 14.90`, `COOKIE: 25.00`. Топ-5 за маржею на цих даних містив би печиво, потім хліб. Запити з таблиці вище наразі не реалізовані й не додають рядків до звіту.

Незмінний контракт поточного звіту: показувати кількості коректних і помилкових рядків, список прийнятих товарів у порядку CSV, список помилок у порядку CSV, загальну вагу, середню маржу та найдорожчий товар. Грошові показники форматуються з двома десятковими знаками, вага — у грамах без дробової частини. Якщо коректних товарів немає, загальна вага має бути `0 г`, середня маржа — `0.00 грн`, найдорожчий товар — `відсутній`; блок топ-5 не є частиною поточного звіту.

## Збірка та запуск

Потрібна Java 21.

Windows PowerShell:

```powershell
.\mvnw.cmd verify
.\mvnw.cmd package
java -jar target/kzp-labv25-chyvantukh-3.0.0-all.jar --input data/input.csv --output data/report.txt
```

Windows Command Prompt:

```cmd
mvnw.cmd verify
mvnw.cmd package
java -jar target/kzp-labv25-chyvantukh-3.0.0-all.jar --input data/input.csv --output data/report.txt
```

macOS та Ubuntu:

```bash
./mvnw verify
./mvnw package
java -jar target/kzp-labv25-chyvantukh-3.0.0-all.jar --input data/input.csv --output data/report.txt
```

Довідка та версія:

```text
java -jar target/kzp-labv25-chyvantukh-3.0.0-all.jar --help
java -jar target/kzp-labv25-chyvantukh-3.0.0-all.jar --version
```

Коди завершення: `0` — успіх, `1` — помилка аргументів або читання, `2` — помилка запису звіту.
