# Параметризоване сховище, винятки й CSV-експорт

## Призначення

Проєкт реалізує лабораторну роботу № 5, варіант 25: розширює консольний застосунок про хлібобулочні вироби узагальненим сховищем, предметними винятками та CSV-імпортом і експортом. Експортер отримує порядок і назви стовпців з анотацій полів через рефлексію. CSV читається й записується в UTF-8.

## Реалізовані компоненти

- `Repository<T>` задає операції додавання, отримання знімка та пошуку за `Predicate<? super T>`. `InMemoryRepository<T>` зберігає порядок додавання й повертає незмінні знімки.
- `BakeryItem` зберігає назву, вид, вагу, собівартість, ціну й час випікання. Інваріанти перевіряються до створення об'єкта; `equals()` і `hashCode()` враховують усі поля.
- `DomainException` є базовим неперевірюваним винятком. Ієрархія містить `ModelValidationException`, `FileFormatException`, `FileAccessException` і `ReflectionException`; файлові помилки зберігають первинну причину як `cause`. Фабрики поточної моделі повідомляють про некоректні значення через `IllegalArgumentException`.
- `Csv.CsvColumn` — анотація з `RUNTIME` retention для полів. Експортер і імпортер знаходять анотовані поля класу та його предків, виключають статичні поля й упорядковують стовпці детерміновано за назвою поля.
- `Csv.Exporter<T>` формує CSV із заголовком, екранує значення та записує файл у UTF-8. `Csv.Importer<T>` перевіряє заголовок і кількість полів, розбирає CSV та створює записи через передану фабрику.

## CSV

Роздільник стовпців — крапка з комою. Заголовки та значення експортуються в одному детермінованому порядку. Поле береться в подвійні лапки, якщо містить крапку з комою, кому, лапку або перенесення рядка; лапки всередині поля подвоюються. Рядки експорту завершуються `CRLF`. Порожній документ, невідповідний заголовок, неправильна кількість полів і некоректне лапкування відхиляються.

Для `BakeryItem` заголовок генерується з анотацій полів у такому порядку:

```text
Час випiкання;Собiвартiсть;Тип;Назва;Цiна;Вага
```

Фабрика імпортера зіставляє значення з назвами заголовків, а не покладається на порядок аргументів конструктора. Перевірка round-trip експортує записи, записує CSV, читає його назад та порівнює відновлені об'єкти з початковими.

## Збірка, перевірка та запуск

Потрібна Java 21.

Windows PowerShell:

```powershell
.\mvnw.cmd clean verify
.\mvnw.cmd package
java -jar target/kzp-labv25-chyvantukh-5.0.0-all.jar --input data/input.csv --output data/report.txt
```

macOS та Ubuntu:

```bash
./mvnw clean verify
./mvnw package
java -jar target/kzp-labv25-chyvantukh-5.0.0-all.jar --input data/input.csv --output data/report.txt
```

CI виконує `clean verify` на Java 21 для Ubuntu, Windows і macOS, перевіряє запуск виконуваного JAR з `--version` та публікує JAR як артефакт. Результати запуску: [GitHub Actions](https://github.com/Chyvantukh/kzp-labv25-chyvantukh/actions/runs/43721862411).

Деталі реалізації, перевірки й відповіді на контрольні питання наведені у [REPORT.md](./REPORT.md).
