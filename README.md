# Консольний застосунок для обробки товарів

## Призначення

Проєкт реалізує лабораторну роботу № 4: обробляє дані про хлібобулочні вироби за допомогою Stream API. Застосунок читає CSV-файл, перевіряє записи, обчислює підсумкові показники та виводить звіт у консоль і файл.

## Модель даних

`BakeryItem` — абстрактний sealed-базовий клас зі спільними властивостями. Об'єкти створюються фабриками `Bread.create(...)`, `Pastry.create(...)` або `BakeryItem.fromCsv(...)`, які перевіряють інваріанти до виклику конструкторів. Підтипи — `Bread` і `Pastry`; кожен реалізує власний розрахунок маржі. Контролер викликає `calculateMargin()` через спільний тип, без перевірок підтипу.

Категорії визначені enum `BakeryKind`: `BREAD` (`хлiб`), `PIE` (`пирiг`), `CONFECTIONERY` (`кондитерський`), `COOKIE` (`печиво`) і `BAKED_GOOD` (`випiчка`). Хлібна маржа враховує 5% виробничих витрат від собівартості; маржа інших виробів — 10% витрат на пакування.

`BakeryItem` також зберігає час випікання у хвилинах. `equals()` і `hashCode()` враховують назву, категорію, вагу, собівартість, ціну та час випікання.

## Зміни відносно лабораторної роботи № 3

У ЛР3 предметну модель було розширено підтипами `Bread` і `Pastry` із різними формулами маржі. У ЛР4 запити до колекцій переведено на Stream API: фільтрацію, перетворення, групування, статистику, сортування та пошук. Формат CSV, перевірку записів і контракт основного звіту збережено.

## Формат вхідного файлу

Новий формат містить шість полів, розділених крапкою з комою; час випікання вказується останнім полем у хвилинах:

```text
Назва;Тип;Вага;Собівартість;Ціна;Час випікання
Хліб пшеничний;хлiб;500;22.00;38.00;35
Печиво;печиво;200;30.00;58.00;18,5
```

Для сумісності також підтримується старий формат із п'ятьма полями; якщо час не задано, модель встановлює `0.0` хв. Час може бути дробовим числом з крапкою або комою. Файл має бути в UTF-8.

## Перевірка даних

- Має бути п'ять (старий формат) або шість (новий формат) полів; назва й тип не можуть бути порожніми.
- Тип має відповідати одному зі значень `BakeryKind`.
- Вага має бути цілим невід'ємним числом.
- Собівартість, ціна й час випікання мають бути скінченними невід'ємними числами.
- Некоректний рядок потрапляє до звіту з номером і причиною помилки; інші рядки обробляються далі.

## Контракти запитів до даних

Усі запити працюють із результатом послідовного читання CSV. Коректні записи створюють `BakeryItem` (`Bread` для `BREAD`, інакше `Pastry`) і додаються до `List<BakeryItem>` у порядку файлу. Некоректні рядки не потрапляють до цієї колекції; причини зберігаються у `List<String>` у порядку рядків CSV.

| Запит | Тип елемента | Джерело | Тип результату та очікуваний результат |
|---|---|---|---|
| Список коректних товарів | `BakeryItem` (`Bread` або `Pastry`) | Вхідний CSV після перевірки кожного рядка | `List<BakeryItem>` у початковому порядку; містить лише прийняті записи. |
| Список помилок | `String` | Вхідний CSV під час перевірки рядків | `List<String>` у порядку появи; повідомлення містять номер рядка й причину відхилення. |
| Загальна вага та середня маржа | `BakeryItem` | Список коректних товарів | `MainController.WeightMargin(double totalWeight, double averageMargin)`. Вага — сума `weightG`; середня маржа — сума `calculateMargin()` / кількість товарів. Для порожнього списку обидва значення дорівнюють нулю. |
| Найдорожчий товар | `BakeryItem` | Список коректних товарів | `BakeryItem` з найбільшою ціною або `null`, якщо список порожній. Якщо ціни однакові, результатом є перший товар у файлі. |
| Фільтр за маржею понад поріг | `BakeryItem` | `List<BakeryItem>` коректних товарів і скінченний поріг | `BakeryQueries.filterByMarginAbove(...)` повертає `List<BakeryItem>` лише з товарами, для яких `calculateMargin() > threshold`. Рівність порогу не проходить; початковий порядок зберігається. |
| Перетворення товарів на список назв | `BakeryItem` | `List<BakeryItem>` коректних товарів | `BakeryQueries.toNames(...)` повертає `List<String>` з `getName()` у початковому порядку; повторювані назви зберігаються. |

### Контракти запитів варіанта

За варіантом 25 виріб містить назву, вид (`BakeryKind`), вагу, собівартість, ціну та час випікання. Усі чотири запити з таблиці реалізовані в `BakeryQueries` і працюють зі списком коректних `BakeryItem`. Вони є окремими операціями запитів і не додають блоків до поточного звіту.

| Запит | Тип елемента | Джерело | Тип результату й контракт |
|---|---|---|---|
| Групування за видом із середньою маржею | `BakeryItem` | `List<BakeryItem>` коректних товарів | `Map<BakeryKind, Double>`: для кожного наявного виду — середнє `calculateMargin()` його товарів. Види без товарів у мапу не додаються. |
| Статистика ваги | `BakeryItem` | `List<BakeryItem>` коректних товарів | `IntSummaryStatistics` за `getWeightG()`: кількість, сума, мінімум, максимум і середнє. Для порожнього списку стандартний результат Java: count і sum — `0`, average — `0.0`, min — `Integer.MAX_VALUE`, max — `Integer.MIN_VALUE`. |
| Пошук за назвою | `BakeryItem` | `List<BakeryItem>` коректних товарів і задана назва | `BakeryQueries.findByName(...)` повертає `Optional<BakeryItem>`: перший точний збіг назви в порядку CSV або `Optional.empty()`, якщо збігу немає. |
| Топ-5 за маржею | `BakeryItem` | `List<BakeryItem>` після відхилення некоректних CSV-рядків | `BakeryQueries.topFiveByMargin(...)` повертає `List<BakeryItem>` із не більш ніж п'яти виробів: маржа за спаданням, за однакової маржі назва за зростанням; якщо маржа й назва однакові, початковий порядок зберігається. |

Для поточного `data/input.csv` парсер приймає 2 товари й відхиляє 4 рядки. Рядок із булочкою має сім полів замість дозволених п'яти або шести, тому він також відхиляється. Основні агрегати: `WeightMargin(700, 19.95)`, найдорожчий товар — `Печиво (58.00 грн)`. Статистика ваги цих двох коректних товарів: count `2`, sum `700`, min `200`, max `500`, average `350.0`; середня маржа за наявними категоріями — `BREAD: 14.90`, `COOKIE: 25.00`. Топ-5 за маржею повертає товари в порядку контракту, максимум п'ять; запити варіанта не додають рядків до основного звіту.

Незмінний контракт поточного звіту: показувати кількості коректних і помилкових рядків, список прийнятих товарів у порядку CSV, список помилок у порядку CSV, загальну вагу, середню маржу та найдорожчий товар. Грошові показники й час випікання форматуються з двома десятковими знаками, вага — у грамах без дробової частини. Якщо коректних товарів немає, загальна вага має бути `0 г`, середня маржа — `0.00 грн`, найдорожчий товар — `відсутній`; блок топ-5 не є частиною поточного звіту.

## Збірка та запуск

Потрібна Java 21.

Windows PowerShell:

```powershell
.\mvnw.cmd verify
.\mvnw.cmd package
java -jar target/kzp-labv25-chyvantukh-4.0.0-all.jar --input data/input.csv --output data/report.txt
```

Windows Command Prompt:

```cmd
mvnw.cmd verify
mvnw.cmd package
java -jar target/kzp-labv25-chyvantukh-4.0.0-all.jar --input data/input.csv --output data/report.txt
```

macOS та Ubuntu:

```bash
./mvnw verify
./mvnw package
java -jar target/kzp-labv25-chyvantukh-4.0.0-all.jar --input data/input.csv --output data/report.txt
```

Довідка та версія:

```text
java -jar target/kzp-labv25-chyvantukh-4.0.0-all.jar --help
java -jar target/kzp-labv25-chyvantukh-4.0.0-all.jar --version
```

Коди завершення: `0` — успіх, `1` — помилка аргументів або читання, `2` — помилка запису звіту.
