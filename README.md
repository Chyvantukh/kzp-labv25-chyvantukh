# Параметризоване сховище та обробка CSV

## Призначення

Проєкт реалізує лабораторну роботу № 5, варіант 25: консольний застосунок про хлібобулочні вироби використовує узагальнене сховище та обробляє CSV із роздільником-комою. Імпортовані записи потрапляють у `Repository<BakeryItem>`, зі знімка якого формується звіт. CSV-експортер доступний як API, але звичайний запуск CLI автоматично не експортує товари. CSV читається й записується в UTF-8.

## Реалізовані компоненти

- `Repository<T>` задає операції додавання, отримання знімка та пошуку за `Predicate<? super T>`. `InMemoryRepository<T>` зберігає порядок додавання й повертає незмінні знімки. Контролер використовує його для зберігання коректних записів, а експортер приймає репозиторій безпосередньо.
- `BakeryItem` зберігає назву, вид, вагу, собівартість, ціну й час випікання. Інваріанти перевіряються до створення об'єкта; `equals()` і `hashCode()` враховують усі поля.
- `DomainException` є базовим неперевірюваним винятком. Ієрархія містить `ModelValidationException`, `FileFormatException`, `FileAccessException` і `ReflectionException`; файлові помилки зберігають первинну причину як `cause`. Фабрики поточної моделі повідомляють про некоректні значення через `IllegalArgumentException`.
- `Csv.CsvColumn` — анотація з `RUNTIME` retention для полів. Експортер та імпортер із заголовком знаходять анотовані поля класу й предків; порядок заголовка визначається назвою поля, а `legacyOrder` задає позиції у файлі без заголовка.
- `Csv.Exporter<T>` формує CSV із заголовком, екранує значення та записує файл у UTF-8. `Csv.Importer<T>` підтримує CSV із заголовком і headerless-формат, дозволяє задавати роздільник і передавати помилки окремих рядків обробнику.

## CSV

Вхідний файл застосунку — CSV без рядка заголовка з роздільником-комою. Позиції полів: назва, вид, вага, собівартість, ціна, час випікання. Наприклад:

```csv
Хліб пшеничний,хлiб,500,22.00,38.00,35
Круасан,кондитерський,90,18.50,55.00,20
```

Для експорту `BakeryItem` формує заголовок і рядки з роздільником-комою:

```text
Час випiкання,Собiвартiсть,Вид,Назва,Цiна,Вага
35.0,22.0,хлiб,"Хліб, ""Пшеничний""
з висівками",38.0,500
```

Експортні колонки впорядковано детерміновано за назвою Java-поля. Для headerless-імпорту позиції явно задаються `legacyOrder`, тому зміна порядку полів у класі не змінює формат вхідного файла. CSV-парсер враховує лапковані значення, коми, лапки й перенесення рядків; просте розбиття рядка за комою пошкодило б такі поля. Некоректні рядки передаються обробнику помилок, а коректні зберігаються в репозиторії.

Порожній документ відхиляється імпортом із заголовком, оскільки в ньому немає обов'язкового рядка заголовка. Імпорт headerless-файла без рядків повертає порожній список.

Експорт виконується явним викликом `Csv.Exporter.write(...)` або `MainController.exportProducts(...)` із коду. У поточному CLI експорт не запускається автоматично й окремої опції командного рядка для нього немає.

## Збірка, перевірка та запуск

Потрібна Java 21.

Windows PowerShell:

```powershell
.\mvnw.cmd clean verify
.\mvnw.cmd package
java -jar target/kzp-labv25-chyvantukh-5.0.0-all.jar --input data/input.csv --output data/report.txt
```

macOS та Ubuntu:

```bash
./mvnw clean verify
./mvnw package
java -jar target/kzp-labv25-chyvantukh-5.0.0-all.jar --input data/input.csv --output data/report.txt
```

CI виконує `clean verify` на Java 21 для Ubuntu, Windows і macOS, перевіряє запуск виконуваного JAR з `--version` та публікує JAR як артефакт. [GitHub Actions для PR #99](https://github.com/Chyvantukh/kzp-labv25-chyvantukh/actions/runs/45030029501).

Деталі реалізації, перевірки й відповіді на контрольні питання наведені у [REPORT.md](./REPORT.md).
